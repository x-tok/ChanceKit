# ChanceKit 验证范围

本文件说明验证方法与证据边界，不保存真实账号、群名、聊天内容或私人资料路径。自动测试的数据均为合成数据。

## 自动验证

准备 Node.js 24+、依赖、固定版本 NapCat ZIP 和 Google Chrome 后，在仓库根目录执行：

```sh
npm run build
npm test
npm run test:e2e
```

## 回归重点

### QQ 与 NapCat 副本

Electron 会把 ASAR 当作虚拟目录。运行目录管理使用 `original-fs`，并通过真实 Electron 后台进程测试这个差异，不能仅依赖普通 Node 文件系统测试。

新副本在独立临时目录完成准备和校验后再替换；替换失败恢复旧副本，遗留 `.previous` 可恢复。NapCat 同版本修复保留配置，QQ 登录资料与消息库不在替换目录中。

退出测试使用自建的子进程和模拟 OneBot 服务。NapCat `bot_exit` 会直接退出、可能来不及回复，因此以进程退出事件确认结果；WebSocket 断开不代表进程已经结束。macOS 的启动入口在登录前就接收私有管道退出指令，不依靠 JavaScript 的 `SIGTERM` 监听覆盖 Electron 原生处理。主程序等待后台清理完成，重复退出请求不能提前跳过等待。

这些测试验证退出指令和等待顺序，不替代特定 QQ 版本的实机验收；验证期间不自动操作真实 QQ 账号。外接 NapCat 的断开测试同时检查服务仍可接受新连接。

#### macOS QQNT 退出回归

标准 Electron 的退出测试无法覆盖 QQ 自带 QQNT 运行库的差异。QQ `6.9.89-45758` 在 `--single-process` 下，即使入口为空白脚本、未登录且未加载 NapCat，`process.exit(0)` 和 `app.quit()` 仍会在原生清理阶段触发 `SIGABRT`。去掉该参数并对副本内的框架与辅助进程一并签名后，管道退出和模拟 `bot_exit` 均返回退出码 0，辅助进程也结束。

已在 Apple Silicon 上执行原生回归的红绿对照：修复前测试因 `SIGABRT` 失败，修复后通过。测试仅修改临时副本，使用空白资料目录和合成 WebSocket 服务，不导入 NapCat、不进行真实账号登录。可显式执行：

```sh
CHANCEKIT_TEST_QQ_APP=/Applications/QQ.app npm run test:native:qq
```

未指定路径或不在 macOS 上时跳过，发布 CI 不依赖安装官方 QQ。该测试不证明登录后的消息完整性，也不替代其他 QQ 版本、Intel Mac 和 Windows 的验收。

### 账号显示

当前登录账号与本地归档账号分开。启动时不把历史账号展示为已登录；停止、取消、断线和失败清空当前账号，离线记录仍可读取。迟到的登录或群列表响应不能恢复已取消的会话。

桌面回归还覆盖两处头像一致、空白昵称、图片加载失败后换号、停止后离线读取以及取消扫码。测试使用可控制响应时机的本机模拟服务，不需要反复登录真实 QQ。

### 数据迁移

目录迁移测试证明文件与 WAL 保留，**不证明系统钥匙串身份兼容**。macOS 应用改名后，旧 `safeStorage` 外接连接配置可能需要在 GUI 中重新填写；原始密文仍保留。

### 日程与模型提取

自动测试只使用合成群消息和模拟 LLM 响应，不发送真实聊天记录，也不消耗真实服务商 API 额度。测试证明消息到 pi 工具调用、结构校验、SQLite 存储与周视图的链路，不证明任一真实模型的活动提取准确率。图片回归覆盖超过 6 张的完整批次、首尾事实汇总、图片中网址保留、二维码解码、动图后续帧、取消和识别失败；桌面回归覆盖 QQ 服务返回附件字节，经主进程图像转换、pi 图片识别，再保存日程的完整链路。

读取器另外实测了反馈中的微信文章、公开飞书报名表，以及 936×10931 JPEG、4725×11812 JPEG 和 9450×23623 PNG，没有发送至真实 LLM。最后一张 PNG 约 2.23 亿像素，缩放后能完整分成两片。群文件使用合成 DOCX 和模拟 QQ 响应验证 `/UUID`、Base64 与文件缓存，不以单元测试代替真实 QQ 在线可下载性的保证。

新反馈清单中的 27 个微信链接已逐条读取正文和图片，均无材料读取警告。其中图片最多的一篇保留了 113 个分片，编码总量约 59 MB，未触发截断。另有一张 QQ 旧图链接仍返回 HTTP 400；重新获取原消息及下载链接的路径通过模拟服务测试，尚未用真实在线 QQ 验证其原图能否恢复。此次构建、81 项专项后端测试和 7 项端到端测试通过，没有调用真实 LLM。

网页解析测试使用受控 HTML/图片，网络策略测试拒绝回环、内网、IPv4 映射 IPv6、非标准端口和重定向到内网。附件接口仅限主进程与消息服务内部通信，不在渲染端命令白名单中；测试覆盖账号/关注范围、取消关注后的迟到响应和离线拒绝。已提取事件仍需用户核对通知原文。当前 Node 26 环境下，既有 `component.test.ts` 的 ZIP 解压测试存在挂起，本轮回归单独运行其余后端测试；组件文件清理仍由 Electron utilityProcess 端到端测试覆盖。

### 非常规招聘消息补充回归（2026-09-20）

新增规则实际进入每次活动 Agent 的系统提示词，不只是保存说明文档。补充覆盖双选会企业展位与纯岗位推广的提示词边界、以原消息时间解释相对日期、未读来源下零活动仍为可重试 `partial`、OCR 未提交和不可辨认的有限补读、补读取消与缓存隔离，以及 `#/...` 报名路由的完整保留和精确校验。模型响应均为模拟数据，不证明真实模型语义准确率。

本次公开读取检查覆盖 13 篇微信文章和 1 个动态投递门户。三篇多图文章实际读取 55/27/19 个图片来源，生成 95/113/116 个分片，没有因分片耗尽漏掉后续整个图片来源；动图抽帧仍保留不完整警告。未向真实模型发送材料，也未改变用户数据库。

构建、93 项后端回归（不含 `component.test.ts`）和 7 项端到端测试通过。另一次全量后端运行重现两项既有组件解压测试分别超过 45 秒，故不宣称全量测试通过。详见[非常规消息处理规则](recruiting-exceptions.md)。

### 跨期事项展示回归

“其他”类且日期跨天的记录独立显示在“跨期事项”，宣讲会、双选会、招聘会、面试和笔试保留原日历展示。测试覆盖已有记录无需迁移、日期区间与所选周相交、日期区间外隐藏、类型/来源/搜索筛选、缺少钟点不误报待核对、真实来源警告保留，以及重启后记录与来源保持不变。

新增带数据的桌面/浏览器验证：报名周期只显示一次，跨天双选会仍按天显示；在 1440、900、375、320px 检查列表及详情，无横向溢出或标题与日期重叠。使用合成单位和日期，不读取或改写用户真实记录。截图位于 `test-results/schedule-ongoing-*.png`，仅用于本地验证，不提交到 Git。

本轮构建和 31 项相关后端测试通过；8 项端到端测试均已通过，其中原有桌面测试首次在断开账号后的截图环节超时，单独复跑通过。未重复执行上文已记录挂起的组件 ZIP 解压测试。

### 减少无效待检查与 PDF 回归（2026-09-20）

完整通知在一次提取后逐项核对事实，跳过补充下载；纯文字岗位推广满足严格条件时零模型调用；网页正文足够时不下载海报。测试验证条件不满足会回退读取，来源未知不能直接归档。“其他场次详见附件”等说明即使伴随一条完整活动，也保留未解决来源的待检查。部分 OCR 得到一条完整活动，不能据此撤销同一海报其余未读内容的警告；需独立正文证据才能认定问题仅来自补充材料。

队列测试覆盖读取诊断与待检查原因分离、旧记录的本地重新判断、证据与警告保留、开启处理才升级重试、账号/关注群范围、同版本失败后不无限重排，以及不完整空结果保留旧活动、成功空结果才清理旧活动。只读检查反馈对应的本地记录发现 12 条待检查、1 条失败；其中 5 条待检查可凭现有原文与活动本地解除提示。本次没有改写用户数据库或调用真实模型，不代表其余海报已经识别成功。

PDF 使用内存生成的合成文档验证文字与链接提取、扫描页转图，并检查转图可见文字正常。真实 Electron 后台测试覆盖 QQ 文件字节 → PDF 解析/转图 → 模拟 pi 识别 → 活动保存；文字 PDF 不增加图像调用，扫描 PDF 走图像识别。未使用用户真实 PDF 做下载验收，也未验证正式 ASAR 安装包。

本轮构建通过；112 项后端测试通过（排除上文已记录挂起的 `component.test.ts`）；8 项端到端测试全部通过。随后新增“材料读取记录默认折叠、无多余待检查”的界面断言，3 项日程端到端测试再次通过。所有模型请求均发往本地模拟服务。

### 公众号标题与引用回复回归（2026-09-20）

标题测试使用受控网页和分享卡片，验证正文标题优先、HTML 实体解码、验证页不作为文章标题、同一卡片对象中的标题与链接配对，以及仅取标题时不下载海报。后台读取最多并发两项，失败缓存避免刷新时重复请求。存储与 Agent 测试覆盖模型失败后保留已经读取的标题、旧通用条目使用本地已有标题补齐，以及标题更新不清除待补全状态、不越过账号与消息版本限制。

引用测试覆盖显式原消息、同目标的较早回复、无关邻近消息排除、原消息后到后重新排队，以及原消息被修改后丢弃正在处理的旧结果。QQ 补取测试拒绝错误编号、群、账号、未来时间、私聊及取消关注后的迟到响应。关联来源共用材料预算，原消息的文字、附件及发送时间一起交给模拟模型。

真实 Electron 配合模拟 QQ 服务补取尚未归档的引用原文及其 TXT 附件：原文发表于 2026-09-23 09:00，写有“明天14:00”；回复发表于 2026-09-24 10:00，补充地点。测试检查模拟模型收到原始时间和附件正文，日程保存为 9 月 24 日，详情可展开引用来源。此结果验证上下文传递与存储展示链路，不代表真实模型已通过相对日期语义准确率评测。
