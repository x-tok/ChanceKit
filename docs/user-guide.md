## 功能一览

| 功能 | 当前行为 |
| --- | --- |
| 首次设置 | 三步完成 QQ 准备、DeepSeek 配置、扫码选群和最近三天的一次性同步 |
| QQ 检测 | 检测安装路径与版本，也可在 GUI 中选择官方 QQ；不自动安装 QQ |
| 内置组件 | 安装包携带固定版本 NapCat，首次连接本地校验、解压，无需访问 GitHub |
| 登录 | 手机 QQ 扫码确认；已有登录资料有效时尝试恢复登录 |
| 外接 NapCat | 支持 OneBot WebSocket，按需配置 WebUI 登录管理 |
| 群聊 | 获取群列表、搜索、关注和取消关注 |
| 历史消息 | 首次设置按北京时间同步最近三天；群消息页仍可手动获取更早记录 |
| 实时归档 | 保存已关注群的新消息；连接中断后重连，并补取最近一页 |
| 本地阅读 | SQLite 存储、消息去重、离线阅读、文字搜索 |
| 消息展示 | 文字、图片引用、链接卡片、附件信息、合并转发文字、原始响应 |
| 导出 | 将本地记录导出为 JSON Lines 文件 |
| 模型配置 | pi agent 的服务商、API 协议、模型和生成参数；密钥加密保存，支持连接测试 |
| 助手 | 普通问答、求职建议，以及招聘官网和本地消息的综合查询；用卡片查看来源与详情 |
| 日程 | 以今天居中的七天日期条选择日期，下方表格直接展示活动名称、时间、地点与原始消息；支持类型/群聊筛选、搜索和详情 |
| 活动提取 | 用户开启后，由独立 pi core Agent 并发处理关注群已归档消息，读取链接正文与图片，结果保存到 SQLite |

## 使用流程

首次打开见机时，按页面中的三步完成初始化：

1. 准备官方 QQ。未检测到 QQ 时，macOS 可直接打开 Mac App Store，Windows 可前往 QQ 官网。安装后先在官方 QQ 登录一次，等待会话和最近的云端消息同步完成。
2. macOS 用户正常退出官方 QQ 并确认副本准备提示。见机会在后续登录时创建约 1 GB 的独立运行副本，不改动官方应用和原聊天库。
3. 配置 DeepSeek V4.1 Flash。填写 API Key 前可从页面打开官方密钥和充值入口；账户需要有可用额度。连接测试通过后，配置会加密保存在本机。
4. 使用手机 QQ 扫描页面二维码，选择需要关注的群聊，然后点击同步按钮。
5. 见机会从北京时间三天前的 00:00 开始同步所选群聊，开启模型整理，并在本次同步完成后断开 QQ。例如 9 月 21 日同步从 9 月 18 日开始。

当前首次设置执行一次性同步，不会在完成后持续连接 QQ。后续可在“设置”中重新连接，在“群消息”中搜索、读取更早消息或导出本地记录；“设置”同时集中管理 QQ 连接与模型配置。

停止本机连接或退出见机时，会先通过 NapCat 的 `bot_exit` 请求 QQ 正常退出并等待进程结束。macOS 在扫码服务尚未就绪时通过私有进程管道发送退出指令；只有进程持续不响应才使用系统终止作为兜底。不会清除登录资料或聊天库，外接 NapCat 只断开消息连接，不退出其 QQ。

## 已有 NapCat

在 GUI 选择“已有 NapCat”，填写 OneBot WebSocket 地址和访问令牌。需要在见机中扫码时，另行启用登录管理，填写 WebUI 地址和令牌。OneBot 与 WebUI 使用各自的认证配置。

本机地址可使用 `ws://127.0.0.1:<端口>`；非本机消息服务必须使用 WSS，登录管理必须使用 HTTPS。不要把访问令牌放到 URL 中，也不要公开 NapCat 管理端口。

## 设置与模型配置

主导航的“设置”集中管理 QQ 连接与本应用 pi agent 的默认 LLM。首次设置只要求 **DeepSeek V4.1 Flash**，调用 ID 为 `deepseek-flash`，协议为 OpenAI Chat Completions；NapCat 地址、端口和令牌不会出现在初始化流程。完成初始化后，设置页仍提供通义千问、Kimi、智谱 GLM、MiniMax 和自定义服务等高级选项。切换服务商会自动选择对应模型、普通 API 地址、协议和参数，不使用 Coding Plan / Token Plan 专属地址。已有配置和密钥不会被默认值覆盖。也可直接输入模型 ID；自定义本机服务可使用 HTTP，远程地址必须使用 HTTPS。

预设目录在浏览器预览和桌面端保持一致，协议适配使用固定版本的 pi-ai。DeepSeek V4.1 Flash 的 ID、上下文和图像能力依据 [DeepSeek 官方模型文档](https://api-docs.deepseek.com/quick_start/pricing) 补充，推理参数依据 [官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode) 映射。

可以配置上下文窗口、最大输出、温度、推理强度和图像能力。DeepSeek V4.1 Flash 默认使用 1M 上下文和 32K 最大输出；日程整理最多使用 60 万字符的日批次输入，并为链接工具返回、推理与最终 JSON 预留上下文。“测试连接”通过真实 pi agent 发出一条固定测试消息，不读取 QQ 消息，可能产生少量 API 费用；可取消，30 秒超时。测试使用当前表单但不会自动保存。

API Key 由 Electron `safeStorage` 加密，只在主进程使用；页面不会回填已保存的密钥。更改服务商、协议或 API 地址后需重新填写密钥，避免旧密钥发往其他服务。系统加密不可用时拒绝保存，不退回明文。浏览器仅提供表单预览，不保存密钥或调用模型。

配置仅作用于见机，不修改 `~/.pi/agent` 或其他 pi 安装。`electron/core/models/pi-model.ts` 的 `createSavedPiAgent()` 可创建使用此配置的 pi agent，日程提取复用同一套模型配置和协议适配。

## 助手

“助手”使用已保存的 pi agent 模型配置，支持普通问答、简历与面试建议、公开网络搜索和本地信息检索。无需连接 QQ 即可使用问答和联网功能；未连接账号的会话与各 QQ 账号的会话分开保存。用户询问某家公司校招时，默认结合网络并优先核对招聘官网，本地无结果不会直接终止查询；明确要求“只查本地”时，Agent 按该范围处理。

本地检索覆盖当前账号已关注群中所有已处理的信息，包括招聘资讯、待补全材料、宣讲会、双选会、招聘会、面试、笔试，以及未生成活动的已处理消息。检索不限于日历当前显示的日期范围，并排除原文更新后尚未重新处理的旧结果。用户可以描述城市、地域、公司或行业、公司性质、岗位名称、技术方向和工作内容；文本组合匹配与结构化属性会在回答中区分。

Agent 的完整规则位于 `electron/core/chat/AGENTS.md`。运行时提供加载 skill、分页筛选本地信息、读取本地原文、搜索网络、读取公开网页和选择结果卡片六个工具。详情工具只能访问本轮本地搜索已返回的消息或活动；卡片选择工具只能引用本轮工具已返回的来源。模型不能执行自由 SQL、读取文件、操作 QQ、登录网站或代为投递。

网络搜索使用 Bing 的公开 RSS 搜索结果，无需额外搜索密钥，其可用性和结果质量取决于搜索服务。网页读取复用现有公开资源下载器，限制大小、超时及重定向，拦截本机/内网地址，不携带模型密钥或登录 Cookie、不执行网页脚本。每轮最多搜索四次、读取六个网页。搜索摘要、已读正文和无法读取的网页会明确区分；动态加载、登录或访问限制可能导致无法核实内容。读取时间不代表发布时间或报名仍开放。

AI 回答支持 Markdown，包括标题、列表、表格、引用和代码块。Agent 通过 `select_chat_results` 选入与回答相关的来源，避免把探索查询中的无关公司混入卡片。卡片使用真实标题并区分本地/网络，每张都能打开详情；正文最多显示四张，超过四条通过“查看全部”弹窗浏览。本地详情包含活动字段、原始消息及附件材料，打开时校验当前账号、关注范围与处理版本。网络详情保存本轮网页正文摘录或搜索摘要、读取状态、网址和时间，支持打开来源网站。

`@earendil-works/pi-agent-core` 的 Dynamic context 在每轮模型调用前注入北京时间日期、联网能力、本地信息数量、已关注群范围和最近对话需求。Dynamic context 不持久化为聊天消息，也不作为信息来源；当前招聘事实必须来自数据库或网络工具。历史对话只保留有界窗口进入模型上下文，工具结果、网页和群消息均按非可信材料处理。

对话保存在本机 `messages.sqlite` 的 `job_chat_sessions` 和 `job_chat_messages` 表中，并按 QQ 账号隔离。删除对话只删除对应的聊天会话，不修改招聘资讯、归档消息或任何 QQ 数据。

## 当前限制

- 历史范围取决于 QQ 接口实际返回值；空群、过期记录和未同步记录可能无法读取。
- 重连只补取最近一页，长时间离线可能有缺口；尚未提供全量历史保证或持续断点回溯。
- 去重目前针对消息重放。不同群转发的同一招聘信息尚未进行语义合并。
- 合并转发仅展开一层文字；图片、语音、视频和嵌套转发保留原始字段，未做完整内容解析。
- 微信接入是后续扩展方向，本版没有微信适配器。

## 常见问题

**没有找到 QQ？** 自行安装官方 QQ 后重新检测，或在文件选择器中选择原始安装。其他工具生成的 QQ 副本不作为安装来源。

**macOS 提示 QQ 正在运行？** 正常退出官方 QQ 后再连接。见机不会主动强制关闭你的官方 QQ。

**二维码没有出现？** 先查看连接活动；如果已有资料恢复登录成功，会直接展示账号。如果使用外接 NapCat，检查 WebUI 地址、令牌及登录管理开关。

**连接成功但没有消息？** 群列表不代表历史已导入。先关注群，再获取最近记录；没有可获取记录的群会展示空状态。

**停止后记录还在，但左下角没账号？** 这是预期行为：当前登录状态已经清空，离线归档仍保留。

**构建提示 NapCat 缺失或损坏？** 执行 `npm run prepare:napcat`，或提供与清单完全匹配的官方 ZIP 后重试。
