# 日历页面设计

## 1. 主题

面向从就业群消息查找当天安排的用户。以日期选择和可直接阅读的表格为中心，沿用见机白底、深绿色及细分隔线，不添加装饰卡片或新视觉体系。

## 2. 配色

复用 `src/App.module.css`：正文 `--ink: oklch(27% .013 159)`，辅助文字 `--muted: oklch(49% .018 157)`，底色 `--panel: oklch(96% .004 157)`，边线 `--line: oklch(90% .007 157)`，强调色 `--green: oklch(47% .087 159)`。选中日期用绿色底与白字，今天未选中时保留文字标记和下划线。

## 3. 排印

沿用系统中文字体。日期数字采用等宽数字，桌面 24px、窄屏 22px；活动名称 13px 加粗，正文原消息 12px，保留换行。日期按钮采用紧凑纵向间距，桌面最小高度 96px、窄屏 88px。以字号、字重和留白区分角色，不依靠阴影。

## 4. 组件

七个原生日期按钮、日期输入、类型与群聊筛选、搜索，以及语义化四列表格。列顺序为名称、时间、地点、原始消息。名称保留活动详情入口，原文与链接直接在表格阅读。多条来源折叠，长原文在单元格内滚动。

## 5. 布局与交互

自动处理状态、开关与处理设置放在日历上方。默认今天前后三天，今天居中；选择窗口内日期只更新下方列表。前后按钮切换七天，日期跳转重新居中，“回到今天”恢复默认。表格之后保留跨期事项、日期待确认与招聘资讯。数据查询沿用 `week` 字段表示七天窗口首日，不再要求周一。

## 6. 层次与反馈

日期条和表头使用浅底色，行之间仅用细线。切换日期立即响应，继承已有指针按压反馈，无入场动画。选中状态使用 `aria-pressed`，今天使用 `aria-current`；表格有表头语义，滚动区域支持键盘聚焦，加载状态与活动数量提供辅助技术提示。

## 7. 数据约定与禁用做法

Agent 经 `submit_activities` 提交结构化字段，应用校验并事务写库。`startTime` 与 `endTime` 独立为 `HH:mm` 或 `null`。仅开始时间显示 `09:30`，起止齐全显示 `14:00–16:00`，仅结束时间显示 `未定–18:00`，均缺失显示 `未定`。地点缺失显示 `未定`。不把占位文字写入日期时间字段，不猜测时间。

原消息从已有归档读取，按当前账号、关注群及筛选条件返回；引用回复保留独立标注。消息作为文本渲染，HTTP/HTTPS 链接走现有外部打开接口，不渲染 JSON，不让 Agent 改写原文。不因本次页面更新自动重新提取历史消息。

## 8. 响应式

桌面四列同时展示，表格最小宽度 720px；窄屏只允许表格横向滚动，页面本身不溢出。日期条始终保留七列，导航与筛选自然换行。检查 1440×900、1280×820、900×640、760×820、375×820 和 320×640。

## 9. 后续修改指引

继续使用 CSS Modules 和已有主题变量。增加字段前优先保留四列阅读路径，更多细节放入既有活动详情。生产内容自动来自数据库，无需替换页面中的示例；端到端测试使用独立合成通知与模拟桥接，示例不会写入用户数据库。
