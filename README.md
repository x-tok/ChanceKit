# 见机 ChanceKit

**不让机会淹没在消息里。**

见机是一个面向就业信息整理的本地桌面应用。从关注的 QQ 群收集消息，保存到本机，方便查找招聘通知、宣讲会和双选会信息。

当前为 **0.1.0 开发版**，已实现 QQ 连接、群聊选择、消息归档、pi agent 模型配置、活动提取与每周日程。更广泛的机会聚合与微信接入尚未实现。本仓库是独立项目，项目名和 npm 包名均为 `chancekit`。

## 当前功能

| 功能 | 当前行为 |
| --- | --- |
| QQ 检测 | 检测安装路径与版本，也可在 GUI 中选择官方 QQ；不自动安装 QQ |
| 内置组件 | 安装包携带固定版本 NapCat，首次连接本地校验、解压，无需访问 GitHub |
| 登录 | 手机 QQ 扫码确认；已有登录资料有效时尝试恢复登录 |
| 外接 NapCat | 支持 OneBot WebSocket，按需配置 WebUI 登录管理 |
| 群聊 | 获取群列表、搜索、关注和取消关注 |
| 历史消息 | 每次请求最近 100 条，支持手动继续获取更早记录 |
| 实时归档 | 保存已关注群的新消息；连接中断后重连，并补取最近一页 |
| 本地阅读 | SQLite 存储、消息去重、离线阅读、文字搜索 |
| 消息展示 | 文字、图片引用、链接卡片、附件信息、合并转发文字、原始响应 |
| 导出 | 将本地记录导出为 JSON Lines 文件 |
| 模型配置 | pi agent 的服务商、API 协议、模型和生成参数；密钥加密保存，支持连接测试 |
| 日程 | 按周展示宣讲会、双选会、招聘会、面试、笔试等活动；类型/群聊筛选、搜索、详情与原消息来源 |
| 活动提取 | 用户开启后，由独立 pi core Agent 并发处理关注群已归档消息，读取链接正文与图片，结果保存到 SQLite |

## 平台与安装

| 平台 | 验证状态 |
| --- | --- |
| macOS Apple Silicon | 已验证本机 QQ 接入和开发构建；正式签名、公证与干净机器安装验收待完成 |
| macOS Intel | 尚未进行实机验证 |
| Windows 10 / 11 x64 | 已实现启动集成与 NSIS 打包配置；真实 QQ 登录、退出和兼容性待验收 |
| Linux | 不支持本机 QQ 自动启动 |

请先自行安装[官方 QQ](https://im.qq.com/)。macOS 首次准备运行副本需要额外约 1 GB 空间，聊天记录和附件引用也会占用空间。

项目目前没有在此 README 中提供正式安装包下载地址。开发者可按下文构建；普通用户收到安装包后，通过 GUI 完成配置，不需要 Node.js、终端或手动编辑配置文件。

### 使用流程

1. 打开见机，在“连接 QQ”中选择“本机 QQ”。未检测到 QQ 时，安装后重新检测，或选择安装位置。
2. **macOS 先正常退出官方 QQ**，再点击“连接 QQ”。应用准备独立运行副本并启动内置 NapCat。
3. 如出现二维码，用手机 QQ 扫码确认。登录成功后点击“查看群聊”。
4. 选择需要关注的群并点击“关注”，开始接收新消息。已有历史通过“获取消息记录”读取。
5. 需要更早记录时点击“从 QQ 获取更早记录”；可搜索、离线查看或导出已归档内容。
6. 暂停采集时点击“停止连接”。头像和当前账号显示会清空，本地记录保留。macOS 可在停止完成后重新打开官方 QQ。

首次连接会读取群列表，不会自动下载所有群的全部历史。只有已关注群的新消息会实时归档。退出见机会停止本应用的采集进程。

### 已有 NapCat

在 GUI 选择“已有 NapCat”，填写 OneBot WebSocket 地址和访问令牌。需要在见机中扫码时，另行启用登录管理，填写 WebUI 地址和令牌。OneBot 与 WebUI 使用各自的认证配置。

本机地址可使用 `ws://127.0.0.1:<端口>`；非本机消息服务必须使用 WSS，登录管理必须使用 HTTPS。不要把访问令牌放到 URL 中，也不要公开 NapCat 管理端口。

### 模型配置

左侧“模型配置”设置本应用 pi agent 的默认 LLM。默认 **DeepSeek V4.1 Flash**，调用 ID 为 `deepseek-flash`；另有通义千问、Kimi、智谱 GLM、MiniMax 和自定义服务。切换服务商会自动选择对应模型、普通 API 地址、协议和参数，不使用 Coding Plan / Token Plan 专属地址。已有配置和密钥不会被默认值覆盖。也可直接输入模型 ID；自定义本机服务可使用 HTTP，远程地址必须使用 HTTPS。

预设目录在浏览器预览和桌面端保持一致，协议适配使用固定版本的 pi-ai。DeepSeek V4.1 Flash 的 ID、上下文和图像能力依据 [DeepSeek 官方模型文档](https://api-docs.deepseek.com/quick_start/pricing) 补充，推理参数依据 [官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode) 映射。

可以配置上下文窗口、最大输出、温度、推理强度和图像能力。“测试连接”通过真实 pi agent 发出一条固定测试消息，不读取 QQ 消息，可能产生少量 API 费用；可取消，30 秒超时。测试使用当前表单但不会自动保存。

API Key 由 Electron `safeStorage` 加密，只在主进程使用；页面不会回填已保存的密钥。更改服务商、协议或 API 地址后需重新填写密钥，避免旧密钥发往其他服务。系统加密不可用时拒绝保存，不退回明文。浏览器仅提供表单预览，不保存密钥或调用模型。

配置仅作用于见机，不修改 `~/.pi/agent` 或其他 pi 安装。`electron/core/pi-model.ts` 的 `createSavedPiAgent()` 可创建使用此配置的 pi agent，日程提取复用同一套模型配置和协议适配。

### 日程与活动处理

1. 关注所需群聊并获取消息，在“模型配置”保存模型及 API Key。
2. 打开“日程”，开启“自动处理”并确认数据发送与费用提示。默认关闭，开关按账号保存。
3. 已关注群的现有归档和后续新消息进入持久化队列，默认同时处理 3 条；可在“处理设置与记录”调整为 1–6 条。
4. 周视图以北京时间、周一为起点，支持上一周、下一周、日期跳转、类型与来源群筛选。宣讲会、双选会、招聘会、面试、笔试等场次继续显示在对应日期；“其他”类且起止日期跨天的报名、招聘周期独立列在“跨期事项”，每项只显示一次，按结束日期排序。该栏随所选周和筛选条件变化，旧记录无需重新提取。无法确认日期的通知仍列在“日期待确认”。
5. 点击活动查看地点、主办方、面向对象、报名截止、报名链接、证据摘录及原群消息。请核对通知原文，模型提取不保证完全准确。
6. 日程下方的“招聘资讯”保留未安排进日历的内容：“资讯推送”收录招聘公告、岗位和投递介绍；“待补全”保留没读全的海报、链接及附件。按原消息发布时间倒序排列，不限日历所选周，提供独立的来源群、原文/文件名搜索和每页 20 条分页。

资讯详情保留标题、摘要、原消息、来源链接与文件名，可打开来源群或重新读取。纯链接优先使用实际取得的文章标题或同一分享卡片里的标题；模型失败也保留已读标题。列表中仍为通用名称的公众号条目会先补用本地已有标题，再按需后台读取公开网页标题：最多并发 2 个、每次 15 秒，不下载海报、不调用模型、不改变待补全状态。验证页或标题读取失败仍使用通用名称；成功缓存 30 分钟、失败缓存 5 分钟，不反复刷新请求。不会编造正文或把群转发自动标为已经核验的官方信息。读取记录默认折叠，顶部“待补全”可直达列表；消息在等待或正在补读时仍保留入口。读全后，有活动则进入日程，非日程招聘内容转为资讯；明确无关的消息不保留资讯卡。真实活动日期未知时仍属于“日期待确认”。

每条消息创建独立的 `@earendil-works/pi-agent-core` 活动 Agent，最多包含同群前三条消息作为上下文；只有当前消息及其明确引用的活动被提取。图片由同一模型配置下的 pi Agent 每批最多 6 张识别来源文字，再汇总全部批次提取活动，长海报首尾的信息可以合并。图片 Agent 仅拥有 `submit_visual_text` 工具，活动 Agent 仅拥有 `submit_activities` 工具；参数经结构校验后由应用事务写库，模型不能直接执行 SQL、读文件或操作 QQ。所有图片、网页及识别后的文字仍是非可信材料，不能作为操作指令。分批识别会增加模型调用；相同账号、模型配置及图片内容的成功识别结果在当前进程中缓存 30 分钟，减少重复识别装饰动图。

招聘相关群二维码作为资讯保留，标题使用“群聊：图片中的完整群名”，不以转发来源群名替代。群名中包含活动日期或“宣讲会”，本身不等同于场次通知；二维码有效期仅在摘要按图片原文注明，不当作活动时间或报名截止。能读清群名时，不因头像或二维码图案无法转写而要求补图；真正模糊的关键文字仍标记待补全。若正文或引用另有明确场次，则提取该活动并在描述中保留群名。旧待补全图片可重新读取应用规则，不自动重跑所有历史图片。

引用回复按 QQ 引用编号查找当前账号同一群的原消息，最多展开 4 条引用链，并带上同一引用目标的最多 2 条近期补充回复（从前 30 条消息中选择），不因普通消息相邻就自动合并。原消息不在本地时，已开启处理且 QQ 在线的任务可最多补取 4 次，经账号、群号、消息编号和时间核对后归档。引用里的链接、图片、文件与当前回复共享整条消息的资源预算；每条消息保留自己的发送时间和材料标记。“今天/明天”依据说出这句话的消息时间解释；提示词要求区分补充、更正和简单致谢。缺失、循环、编号歧义或超限引用仍保留待补全提示，不假装读全。资讯与活动详情可展开引用原文；引用来源迟到或修改后，相关回复重新排队，旧结果不能继续提交。

非常规招聘消息规则会实际注入每次 pi 提取：企业参加双选会属于日程；只有职位、内推码或网申入口的推广不创建日程，但明确给出起止日期的跨日报名周期可作为“其他”类跨期事项保留；只有截止日期时不猜测开始日期。毕业届别、文章推荐和编辑日期不能当作当前活动时间。跨期事项不因缺少具体钟点而标记待确认，真实来源警告仍保留。图片未结构化提交或有文字无法辨认时，优先按模型指出的分片位置补读，每批最多 2 张，每条消息最多 6 次补读；补读仍不完整时保留可读来源及记录，不因某一批缺失而丢掉正文已明确的活动。详见[非常规消息处理规则](docs/recruiting-exceptions.md)。

网页读取支持公开 HTTP/HTTPS 正文、分享卡片链接和网页图片（含常见懒加载图片）。微信文章使用兼容浏览器的请求头并优先提取文章标题、正文；公开飞书表单从页面自带的静态数据提取标题、说明和可见场次选项，不执行网页脚本。来源保留原始分享链接，不保存跳转生成的临时认证令牌。只有实际返回验证或登录页面时才记录相应限制。

多图网页（至少 8 张图片）或图片链接明确标示 GIF 时，桌面端在隔离浏览器中打开原始网址，加载网页本身的 DOM、样式和脚本，滚动触发懒加载、等待图片与字体后，直接使用 Chromium 的“保存为 PDF”。不提取图片拼接 PDF、不重建文章排版、不选择动图首末帧，也不替换网页的打印样式。正文已足够确认日程时仍跳过补充读取。PDF 是静态打印结果，不能完整表示动画、折叠区域或交互内容；图片缺失、滚动未完成和可疑裁切容器会保留诊断，不把打印成功视为内容完整。PDF 生成失败不自动退回大量逐图处理。

网页 PDF 每篇浏览器加载与打印限 120 秒、24 MB，最多 768 次资源请求、128 MB 下载数据，最多同时下载 8 项；资源仍通过绑定 DNS 的公开下载器获取，不携带用户登录信息或模型密钥。临时浏览器无应用接口，禁止表单提交、下载、弹窗、嵌入页面、工作线程和非公开网络请求。桌面读取每批最多 4 个图像页，识别完再继续后续页，不再累积到原有的 24 个图像页或全消息 128 个分片上限。安全页数上限为 256 页，读取与模型调用共享整条消息的 10 分钟限时及 6 次补读额度。每篇保留最多 4 万字可提取正文、10 万字分批识别文字，为后续批次预留份额；含网页 PDF 的消息材料最终文字上限为 16 万字，实际截断仍提示。快照按账号保存，每账号保留最近使用的 100 份或 256 MB；重新读取会重新加载原网页，不复用旧拼图 PDF。来源详情优先显示“网页 PDF”及实际处理页数，超过 3 张的来源图片折叠展示；处理页数不等于原网页内容完整。旧网页可手动重新读取，不自动批量重跑历史。少图网页、QQ 独立图片和普通 PDF 附件仍使用原路径。

图片交给模型前由 sharp 解码、校正方向并转换成 JPEG；长海报按最多 1600×2200 像素分段，相邻分片重叠以保留跨边界文字。动图在预算内读取所有帧，只去掉像素完全相同的重复帧，再按顺序拼图；预算不足时跨时间线抽帧并明确标记。长图抽片也在预算允许下保留首尾。二维码在本机解码；网页明文网址及图片识别中明确出现的网址也计入报名链接来源，不允许活动模型凭空猜测链接。来源及报名链接保留 `#/...` 前端路由，避免跳到错误页面。

每条消息最多读取 4 个页面、2 个文件；普通逐图路径最多 96 个网页/消息图片来源、128 个图像分片，编码后总量 72 MB，为后续图片预留份额，避免开头动图耗尽额度。网页 PDF 分批路径采用上一段的独立限制。网页/文件 5 MB、响应类型为图片的资源 20 MB、单资源 30 秒超时、最多 8 次跳转，整条消息最多 10 分钟。静态图输入上限约 2.68 亿像素，缩放后最多 3200 万像素；普通逐图路径的动图最多 240 帧、累计 8000 万像素。正文长度也有限制，超出真实安全上限仍会提示，不伪装成完整读取。公开图片下载有有界内存缓存，请求同一网站时限速；微信临时验证页只延迟重试一次，不绕过验证。DNS 在实际连接时校验并绑定，拒绝本机、内网、凭据 URL 和非标准端口，不携带浏览器 Cookie 或模型 API Key。公开材料下载直连，模型请求使用 Electron 系统网络设置。

群文件支持 PDF、DOCX 正文、图片和报名链接，以及 UTF-8 TXT、MD、CSV 文本。PDF 优先提取文字与链接，扫描页或含图页转图后交给现有识别链路；最多 20 页、8 个转图页、累计 2000 万输出像素、30 秒，超限和加密仍保留读取记录。PDF 字体资源仅从随应用安装的依赖读取，不跟随文档请求外部资源。通过已连接 QQ 获取当前账号、已关注群归档消息中的附件，支持旧式 `/UUID` 文件 ID、下载 URL 和 Base64 数据。过期图片或旧文件 ID 会尝试重新读取原消息，并核对群号、发送者、时间和附件位置。托管 QQ 返回本地文件时，只读本应用私有 QQ 缓存内匹配文件名、大小的普通文件，拒绝越界路径和符号链接逃逸；不读取外接 NapCat 返回的任意本机路径。DOCX 禁止外部文件访问，解压最多 1000 项、20 MB。需要 QQ 的附件在离线时保留为“待检查”，并显示具体失败原因。

完整消息会先提取并核对日期、钟点、地点与原文证据，通过后不再展开补充网页和海报；网页正文已完整支持日程时，也跳过补充图片。含“详见附件”“其他场次”等依赖说明不适用快速路径。满足严格条件的纯文字岗位推广直接归档，无需模型调用；链接、图片或附件内容未知时不会直接判为无活动。

读取记录与待检查原因分开保存。正文已确认日程时，补充材料读取问题仅出现在详情中默认折叠的“材料读取记录”；仍无法确认的海报、附件等进入“招聘资讯 → 待补全”，无需在处理设置里阅读大段错误。实际需要登录或验证码的页面、没有静态内容的动态网页、旧版 DOC、音视频和合并转发展开内容仍无法自动读取；相关记录和来源不会被隐瞒或删除。

更新后需重启桌面应用使处理引擎生效。旧待检查记录先用本机原消息与已存活动重新核对，无需调用模型；剩余旧失败/待检查记录仅在自动处理已开启时，按处理版本进入一次有上限的升级重试，范围限当前账号的关注群。关闭自动处理不会发起模型请求，也可手动重试。空结果且来源未读全时保留上次活动，避免失败补读误删已提取内容。

队列按消息内容版本去重。失败最多尝试 3 次，按 5 秒、10 秒延迟重试；超过后保留失败记录供手动重试。暂停、换账号、换模型或取消关注会取消相关请求，过期任务不能写入结果。应用退出后未完成任务在下次启动恢复；停止 QQ 连接仅停止采集，已开启的归档处理仍可继续。活动根据标题、主办方、日期、时间和地点保守合并重复转发，并保留各消息来源，不执行模糊合并。

新增 SQLite 表：`activities`、`activity_sources`、`schedule_jobs`、`schedule_settings`、`recruiting_information`。首次创建资讯索引时，仅在本机恢复旧的失败/待检查消息，以及无已存活动且原文可识别为招聘信息或公众号分享的已完成记录；不会为建立资讯列表重新请求模型，不会补出未保存的历史网页摘要。既有消息库不删除消息或关注状态；活动、资讯、队列和处理开关与 QQ 账号隔离。取消关注后列表及详情均不可见，消息被编辑后旧资讯按内容版本立即失效。

## 数据、隐私与 QQ

### 数据保存位置

| 环境 | 数据根目录 |
| --- | --- |
| macOS 安装版 | `~/Library/Application Support/ChanceKit/` |
| Windows 安装版 | `%APPDATA%/ChanceKit/` |
| 源码开发 | 仓库内的 `.dev-data/` |
| 自动测试 | 测试创建的独立临时目录 |

数据根目录中包含：

```text
messages.sqlite          消息、群列表、关注状态、活动与来源、处理队列及开关
messages.sqlite-wal      SQLite 写入日志，运行时可能存在
messages.sqlite-shm      SQLite 共享内存文件，运行时可能存在
connection.enc           系统凭据加密支持可用时保存的外接连接配置
model-settings.enc       加密保存的 pi agent 模型参数与 API Key
exports/                 消息导出临时文件
runtime/
  napcat-4.18.28/         解压后的组件及其 config/ 配置
  QQRuntime.app/         macOS 的 QQ 运行副本
  qq-profile/            macOS 采集进程的独立 QQ 登录资料与原生数据
```

消息正文与原始响应保存在本机，业务 SQLite 库目前**没有整库加密**。外接连接配置使用 Electron `safeStorage`；NapCat 自身运行所需令牌保存在私有运行目录的配置文件中。因此整个数据目录都应当视为私人资料，不能作为反馈附件或提交到 Git。

默认不把 QQ 消息发送给 LLM。只有在“日程”确认开启自动处理后，关注群的归档消息、少量同群上下文及链接/图片/支持的群文件内容才会发送给已配置的模型服务商，可能产生费用。暂停不保证撤销已计费的请求。“模型配置”的连接测试仍只发送固定测试消息。联网连接 QQ/NapCat、加载 QQ 头像、读取公开材料和打开外部链接时，会访问相应服务；图片与附件保存的是上游引用，链接可能失效。

### 与官方 QQ 的关系

macOS 会复制官方 QQ 应用到见机的数据目录，只修改和签名副本。**应用副本与官方 QQ 的原始聊天库是隔离的**：不会自动导入官方 QQ 的旧本地记录，也不保证将采集期间的数据写回官方 QQ 原来的数据库。重新打开官方 QQ 后的云端同步行为，仍由 QQ 决定。

Windows 使用 NapCat 提供的启动组件，不改写官方 QQ 安装文件；QQ 原生资料位置由其自身决定，不能套用 macOS 的目录隔离结论。

NapCat 登录使用 QQ 客户端会话，不是腾讯开放平台 OAuth。第三方接入的兼容性和账号状态取决于 QQ 与 NapCat，不能保证所有版本可用或绝无风控影响。不要为了验证功能频繁切换真实账号或反复登录。

### 更新与数据保留

重新安装或构建后，会检查 QQ 副本的来源、加载入口和签名再决定是否复用。需要重建时先准备临时副本，再替换正式目录；替换失败尝试回滚。组件修复不会清理 `qq-profile` 或业务消息库。

从旧版“群讯”迁移时，仅在 `ChanceKit` 目录不存在的情况下整体搬移旧数据目录；两者同时存在时不覆盖、不合并。QQ 登录资料与已归档消息保留。**macOS 改名可能导致旧版 `safeStorage` 加密的外接 NapCat 配置无法解密，需要在 GUI 中重新填写地址与令牌**；搬移旧密文不等于系统钥匙串身份也完成迁移。

## 开发与构建

### 环境

- Node.js 24 或更新版本及 npm。
- macOS 或 Windows 开发环境。正式安装包在对应目标系统构建和验收。
- Electron 自动测试不需要真实 QQ 账号；浏览器布局测试使用本机 Google Chrome。
- 首次安装依赖和准备 NapCat 的构建机器需要网络，也可预置与清单匹配的官方组件 ZIP。

在仓库根目录执行：

```sh
npm ci
npm run prepare:napcat
npm run dev
```

`npm run dev` 启动 Vite 和 Electron，开发界面默认端口为 5178，占用时自动换端口；连接 QQ 仍需在 GUI 中主动操作。仅查看界面可运行 `npm run dev:web`，浏览器预览没有 QQ 接入能力。

`dev`、`start` 和 `test:e2e` 会先检查 Electron 运行文件，缺失时调用官方安装器下载并校验，代理选择与 NapCat 下载一致。也可单独执行 `npm run prepare:electron`。安装包已缓存或运行文件已就绪时会直接复用，不需要删除 `node_modules` 或重装全部依赖。

### NapCat 如何随包分发

固定版本、官方 URL、文件大小和 SHA-256 位于 [resources/napcat/manifest.json](resources/napcat/manifest.json)。维护者执行 `prepare:napcat`，将校验通过的原始 ZIP 放入 `resources/napcat/`；此 ZIP 不提交到 Git。

下载优先使用 `HTTPS_PROXY` / `HTTP_PROXY`（也支持小写），其次使用 npm 的 `https-proxy` / `proxy` 配置；均未设置时，macOS 自动读取系统的 Web / Secure Web 代理。`NO_PROXY` 可指定不走代理的域名，设置为 `*` 则全部直连。脚本不修改系统代理，不使用第三方镜像；连接超时或临时网络错误最多尝试 3 次，每次仍校验固定大小和 SHA-256。

如果 GitHub 直连超时，可显式指定本机 HTTP 代理（端口按实际配置调整）：

```sh
# macOS / Linux
HTTPS_PROXY=http://127.0.0.1:7890 npm run prepare:napcat
```

```powershell
# Windows PowerShell
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
npm run prepare:napcat
```

也可从清单中的官方 URL 手动下载，将 ZIP 放到 `resources/napcat/NapCat.Shell.zip` 后重试；已通过校验的文件不会重复下载。

构建和打包都会再次校验组件。缺失或损坏时直接失败，不生成缺少组件的安装包。打包时 ZIP、清单和来源说明一起进入应用资源目录；最终用户首次连接只从安装包解压，不需要下载 NapCat，也不需要访问 GitHub。QQ 的正常联网仍然必需。

## 项目结构

```text
src/                    React 界面、品牌、共享协议与桌面桥接
electron/main.ts        窗口、系统凭据、文件选择、导出与 IPC

resources/napcat/      固定组件清单与来源说明
scripts/               开发、构建、组件准备与打包校验
tests/                 协议、存储、迁移和 Electron 测试
docs/                  接入细节与验证范围

```

技术栈为 Electron、React、TypeScript、Vite 和 Node.js SQLite。渲染进程不直接操作 QQ 或数据库，消息服务运行在独立后台进程，通过受限 IPC 与界面通信。

## 当前限制与后续方向

- 历史范围取决于 QQ 接口实际返回值；空群、过期记录和未同步记录可能无法读取。
- 重连只补取最近一页，长时间离线可能有缺口；尚未提供全量历史保证或持续断点回溯。
- 去重目前针对消息重放。不同群转发的同一招聘信息尚未进行语义合并。
- 合并转发仅展开一层文字；图片、语音、视频和嵌套转发保留原始字段，未做完整内容解析。
- 后续计划包括独立 Agent 抽取模块、多模态及链接解析、结构化 JSON 落库、并发调度和机会去重；这些功能尚不可配置或使用。
- 微信接入是后续扩展方向，本版没有微信适配器。

## 常见问题

**没有找到 QQ？** 自行安装官方 QQ 后重新检测，或在文件选择器中选择原始安装。其他工具生成的 QQ 副本不作为安装来源。

**macOS 提示 QQ 正在运行？** 正常退出官方 QQ 后再连接。见机不会主动强制关闭你的官方 QQ。

**二维码没有出现？** 先查看连接活动；如果已有资料恢复登录成功，会直接展示账号。如果使用外接 NapCat，检查 WebUI 地址、令牌及登录管理开关。

**连接成功但没有消息？** 群列表不代表历史已导入。先关注群，再获取最近记录；没有可获取记录的群会展示空状态。

**停止后记录还在，但左下角没账号？** 这是预期行为：当前登录状态已经清空，离线归档仍保留。

**构建提示 NapCat 缺失或损坏？** 执行 `npm run prepare:napcat`，或提供与清单完全匹配的官方 ZIP 后重试。
